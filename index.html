Every disagreement is a place to look.

Run two pipelines or import their VCFs. You’ll see shared alleles, unique calls and genotype agreement. Inspect disagreements in the read evidence: agreement between callers does not establish accuracy.

A PRACTICAL WITH MORE THAN ONE ROUTE

Design a fair comparison.

Work in pairs or small groups. Your aim is to explain why two pipelines disagree, using the evidence in their outputs. There is no required sequence of buttons and no single winning pipeline.

1. Make a prediction

Choose human loci or yeast mitochondria. Decide what you will vary and what you will hold constant. Predict where errors or disagreements might occur: low coverage, repeats, indels, low base quality or the mitochondrial origin.

2. Build two pipelines

Use the terminal, the Galaxy-style forms, or both. Both use the same files and execution engine. Choose an aligner, sort the SAM to BAM, index it, then call variants. Names are yours to choose; avoid overwriting a result you still need.

3. Compare fairly

Use the same reads, reference, region, filters and ploidy unless that is your experimental variable. Normalize before comparing. Check the actual alleles and genotypes, not only the number of VCF rows. Agreement is not proof of accuracy.

4. Explain one difference

Inspect the BAM with samtools view, depth or mpileup. Use bcftools query to inspect allele depths and quality. Is a unique call supported by both strands? Could alignment or a repeat explain it?

Start with a small experiment

The scratchpad provides an editable starting pipeline, not a prescribed answer. Try minimap2 and Bowtie2 with the same bcftools model, then use the same BAM with multiallelic and consensus calling. exactSNP offers a separate SNP-focused algorithm and can also report simple CIGAR indels. It supplies no sample genotype field. Its SNP QUAL is capped −log10(p), not Phred; simple indels receive QUAL=1. Do not reuse a numerical bcftools QUAL cutoff.

samtools flagstat results/alignment.bam
samtools view results/alignment.bam contig:start-end
bcftools query -f '%CHROM\t%POS\t%REF\t%ALT\t%QUAL\n' results/calls.vcf
awk '!/^#/ {print $1, $2, $4, $5}' results/calls.vcf
What runs here?

All bundled programs run on the supplied bytes. No alignment or variant-call result is replayed. This is a Galaxy-style teaching interface, not a Galaxy server.

Bowtie2 is markedly slower in this older browser build: a full dataset can take many minutes. Start with minimap2, or prepare smaller paired FASTQ subsets for quick experiments. A subset changes coverage and the evidence available for calling. Single-threaded browser timings measure this implementation and device. They are not a native performance benchmark. Small reference slices also omit genome-wide alternative mappings, so their mapping qualities are not equivalent to whole-genome alignment.

Unix commands in the browser

Use help for the available commands. Pipes, input/output redirection, quoted arguments, simple globs, variables and command chaining work. GNU awk, grep, sed and common text utilities process actual files. Shell loops, process substitution, background processes, package installation and arbitrary executables are not implemented.

Know your dataset

These are small subsets of biological sequencing data from public archives: NA12878 human exome reads and yeast genomic reads enriched for mitochondrial alignments. Read sequences and the quality scores stored in the source files are retained. The NA12878 FASTQs are recovered from an upstream recalibrated BAM; they are not presented as untouched basecaller output. No variants have been introduced. Read the accession and extraction details in the dataset provenance.

Human examples use a diploid model. Haploid calling is a starting model for the yeast mitochondrial data, not evidence that the sample is homoplasmic. Mitochondrial copy number is not ploidy. Low-frequency alleles require examining sequencing errors, mapping ambiguity and possible heteroplasmy. Reads crossing the circular mitochondrial origin can be missed or clipped against a linear reference. Inspect that boundary separately.

All VCF coordinates refer to the FASTA contig names shipped with the dataset. Reference slices use local coordinates; consult the dataset manifest before converting them back to genome positions. Do not mix assemblies or references.

No benchmark truth set is bundled. The comparison reports agreement, not sensitivity or precision. A valid benchmark would require a matching independently established callset and high-confidence regions. Read extraction based on an existing alignment also favours reads that mapped in that source pipeline; consider that selection bias.

What to hand in

A question and prediction; the commands and parameter choices for each run; an allele-level comparison; evidence for one disagreement; and a short account of limitations. Export your experiment to keep inputs, outputs, notes and the command journal. Keep uncertainty visible.
